# P4 通用实验与比较

父任务09-28-ferrots-implementation；开发分支dev；状态planning。

## Goal

先交付可追溯的模型比较、静态报告和五个公共数据集实验，再按独立增量交付rolling-origin回测和搜索。新增模型逐个规划，避免所有候选阻塞第一个可用报告。

## 前置

比较/报告可消费P1/P2已经交付的结果；Informer与WaveForM是否进入正式矩阵取决于各自验收。P2未完成条款不在本任务自动豁免。每个增量实施前审批设计与预算，不提前实现P5。

## Requirements

- P4-R1：rolling-origin回测，每折重新拟合scaler/训练状态；水泥折边界在运行段边界上，不混合不同forecast_origin对同一目标时间的预测。
- P4-R2：compare输出同协议多run指标；数据指纹、切分、变量语义、评价窗口和单位不一致时拒绝。不同代码/设备的同协议结果可展示但必须标明身份和公平性边界。
- P4-R3：网格/随机搜索记录预算、种子、配置和验证指标；只用验证集选择，最终配置独立评价测试集，搜索不反复读取测试标签。
- P4-R4：一张CUDA卡一个独立实验，保存任务与设备/attempt对应关系，失败任务可独立恢复；不称分布式训练。先保留现有手动/脚本调度，未遇当前需求不建复杂调度平台。
- P4-R5：静态Markdown/HTML报告含指标、分变量/步长统计、可用预测曲线，私有报告不嵌入原始行；输出只留忽略目录，公开docs/results为统计。
- P4-R6：PatchTST为优先候选，TCN、TSMixer及独立的TimeMixer为后续候选；选中后建独立任务，要求结构、CUDA梯度、公共/水泥实验和能力表。不在本任务强制同时实现全部候选。
- P4-R7：分阶段性能剖析包含解析、打包、传输、前后向、更新、验证、写盘；CUDA计时同步，显存来源明确。
- P4-R8：先用现有JSON/JSONL/CSV运行产物；SQLite索引保持可选，只有实际查询规模需要时再提出，不作为首阶段验收。
- P4-R9：按custom-lsf-v1在Weather/Exchange/ECL/Traffic/ILI运行DLinear、iTransformer、Informer（通过后加入WaveForM及其他已完成模型）。每模型5×4H×3种子=60个Rust格；首批三模型180格；均值/总体标准差与公开参考来源并列，不设论文数值门。

## Acceptance Criteria

- [ ] P4-AC1：compare拒绝不同数据/协议/切分/单位，接受同协议结果并显示源码、设备和种子；P1单种子历史参考标n=1，不能填造std。
- [ ] P4-AC2：比较表及Markdown/HTML报告可从绑定产物重建，汇总与逐run数值一致；预期缺失模型格显式标缺失，私有报告无原始行。
- [ ] P4-AC3：五公共数据集首批180格全部正常完成且身份/窗口/退出检查通过。失败/缺失清单仅是阶段报告，存在未完成格时本项保持未通过；延期须有明确决定，不能把披露失败当作完成。每组均值/std、配置来源与公开参考写入docs/results，ILI使用L36/H24、36、48、60。
- [ ] P4-AC4：ETTh1与cement-twin回测完成；每折scaler仅fit该折训练段，折/窗口/forecast_origin身份可核查且无跨折训练状态泄漏。
- [ ] P4-AC5：搜索每试验记录配置、预算、seed和验证指标；用可观测读入记录证明选择阶段不访问测试标签，最终选定配置只评价一次测试集。
- [ ] P4-AC6：单卡独立实验及双卡两实验可追溯，失败只恢复对应attempt；阶段耗时与峰值报告可核验。
- [ ] P4-AC7：每个被正式纳入的新模型独立任务验收，至少ETTh1四H与水泥三H、各三seed完成；本任务不以候选清单代替训练证据。
- [ ] P4-AC8：相关CUDA质量门、工具测试、私有数据检查及最终证据评审通过；汇总能力表与docs/results按实际状态更新。

## Out of Scope

分布式训练、桌面UI、强制SQLite、新实验服务、低精度与未审批的全部候选模型实现。保留P5发布后门槛。
